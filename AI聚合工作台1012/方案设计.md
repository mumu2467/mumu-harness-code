## 1. 既有资产盘点（重要，省掉大量试错）

工作区已有 `AI大乱斗1010`（Electron 桌面版，把同一段文字+图片同时发到豆包/DeepSeek/Kimi 网页版）。
它**已经用真实站点跑通过**，下列结论直接迁移，不用重新踩：

| 资产 | 体积 | 复用方式 |
| --- | --- | --- |
| `adapters/site-config.js` | 8KB | **直接复用**：三家站点的多候选选择器（输入框/发送键/上传框/登录探测/二维码/风控词） |
| `adapters/page-utils.mjs` | 42KB | **直接复用**：注入网页侧的工具库（原生 setter、DataTransfer 造图、`snapshotMessages`/`diffNewMessages`/`extractLastAnswer`/`isGenerating`/`countMessages`、调试高亮） |
| `adapters/base.mjs` | 71KB | **移植宿主机侧逻辑**：Electron 的 `executeJavaScript`/剪贴板/`sendInputEvent`/CDP 换成 Playwright 的 `evaluate`/`keyboard`/`setInputFiles`/`newCDPSession` |
| `test/*.mjs` | 34KB | 移植到新项目做注入脚本回归（jsdom，离线可跑） |
| `adapters/preferences.mjs` | 6KB | 复用"最佳模型/推理强度"档位优先级 |

**已经实测过的坑（写进代码注释，不重复犯错）：**

1. 长文本一次性注入会被内核**静默截断**（豆包实测）→ 必须**分块 20 字**（走 CDP `Input.insertText`）。
2. 直接改 `innerHTML` 在 Lexical/ProseMirror 上"看着有字、其实没字"（发送键仍禁用）→ 必须用原生 setter / `insertText`，并先让输入框真正获得焦点。
3. 回答结束**不能**用"停止生成按钮消失"判定（三站都匹配到常驻元素，会永远卡在"生成中"）→ 用**文本稳定 4.5s**。
4. 三家都把**思考过程**渲染在页面上（DeepSeek `ds-think-content`、Kimi `thinking-container`、豆包"已思考"）→ 抓取时必须排除。
5. 页面**不能压小**：`display:none` 会让输入框拿不到焦点；176px 高会让站点切折叠布局、DeepSeek 发送键消失 → 必须保持接近正常尺寸（1280×900）并**离屏摆放**。
6. 点发送前要等约 450ms 让编辑器内部模型同步，否则"有字但按钮禁用、点了没反应"。

## 2. 路线选型

### 为什么不能 iframe（前提确认）

三家 C 端网页版均下发 `X-Frame-Options` / CSP `frame-ancestors`，浏览器层面直接拒载。
"自建反代剥掉响应头"这条路**不采用**，原因有三：
页面内的 SPA 仍会带自己的域名/Cookie 请求其后端，反代必须同时改写 HTML、JS、接口、Cookie 作用域，等于对站点做 MITM；
三方登录凭据会流经我们的服务端；且明确违反站点服务条款。

### 路线 A（默认，采用）

后端 Playwright 驱动**真实浏览器上下文**，登录态用 `launchPersistentContext(userDataDir)` 落盘持久化；
前端 WebSocket 通信；后端负责投递（文字+图片）、监听回复流、差分抓取答案、回传增量。

- 优点：就是"C 端窗口"本身，无需任何 API Key，能吃到网页版独有的模型/联网/文件能力。
- 代价：需要浏览器进程（3 个上下文约 1.5–3GB 内存）；选择器随站点改版会失效（用多候选+诊断接口降本）；风控/验证码必须人工介入；同一站点必须串行发送。

### 路线 B（同层可切换，采用）

三家官方 API（DeepSeek 开放平台 / 火山方舟豆包 / Moonshot Kimi）统一封装成同一套 SSE → `reply.delta/done/error` 事件。

- 优点：稳定、快、多模态正规。
- 代价：需要 Key 与计费；回答与 C 端网页版可能不一致。

### 路线 C（hybrid，采用为兜底）

`ADAPTER_MODE=hybrid`：优先 API，API 失败（无 Key / 限流 / 超时）自动落到 Playwright 通道，前端事件模型完全一致，用户无感。

### 抽象层（关键）

```ts
// 三家共用的唯一扩展点：新增 AI 只需实现这个接口并注册
export interface ChatAdapter {
  readonly id: Provider;
  readonly label: string;
  /** 启动/首次调用时准备（打开页面、加载持久化登录态） */
  ensureReady(): Promise<void>;
  /** 登录态探测：未登录时返回 needLogin + 人工介入提示 */
  loginState(): Promise<LoginState>;
  /** 投递一条消息，通过 sink 回吐流式事件 */
  send(input: SendInput, sink: ReplySink, signal?: AbortSignal): Promise<SendResult>;
  /** 停止生成 */
  stop(): Promise<void>;
  /** 站内开新会话 */
  newSession(): Promise<void>;
  /** 选择器命中诊断（站点改版排查用） */
  diagnose(): Promise<DiagReport>;
  dispose(): Promise<void>;
}
```

`ProviderBus`：**跨站点并行、同一站点串行**（同一站点并发会让 DOM 差分串台，这是正确性问题，不是性能优化）。

## 3. 关键技术决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 图片传输 | 前端 canvas 压缩（≤1600px / JPEG q0.85）后 **multipart 上传**，后端落盘返回 `imageId` | 三站上传都必须塞**磁盘文件**（`setInputFiles`/CDP `DOM.setFileInputFiles`）；base64 直接传会多 33% 体积且仍要落盘 |
| 流式抓取 | 900ms 轮询 `snapshotMessages` + `diffNewMessages` 差分，文本稳定 4.5s 判定结束 | 复用旧项目已验证算法；不猜"哪个 div 是消息列表"（DeepSeek 类名一直变） |
| 答完判定 | 文本稳定 4.5s（辅助：见过停止键且消失可提前收工；兜底：总超时 180s） | 实测唯一可靠判据 |
| 登录窗口 | 首次 `LOGIN_MODE=1` 窗口在屏内可见（人工扫码/滑块）；日常 `--window-position=-32000,-32000` 离屏 | 不自动破解验证码；离屏可保持 Chromium 正常合成与尺寸 |
| 风控介入 | `POST /api/providers/:id/recall` 用 CDP `Browser.setWindowBounds` 把窗口**拉回屏幕**给人工处理 | 只提示与让位，不绕验证 |
| 观测窗 | v1：按需 `page.screenshot({type:'jpeg',quality:60})` 2fps → WS `view.frame` | 比 `Page.startScreencast` 简单得多且无需处理 ack/丢帧；15fps 流畅观测代价约 5MB/s（3 窗），v2 再上 |
| token 估算 | 中英混排启发式（CJK 字≈1.5 token/字，其他≈4 字符/token） | 网页版拿不到真实 usage，UI 上明确标注"估算" |
| 首字延迟 | 发送成功时刻 → 首个 `reply.delta` 时刻 | 与总耗时分开显示 |
| 数据库 | `node:sqlite`（`DatabaseSync`） | Node 24 内置，避免 `better-sqlite3` 的 node-gyp 原生编译（本机无 VS 构建链） |
| 断线恢复 | WS 带 `seq`；重连时后端把 `status in (pending,streaming)` 的回复**先重放快照**再接增量 | 手机上切后台不断流 |
| 前端栈 | React 18 + Vite + TS + Tailwind + zustand | 轻量、无框架级状态复杂度；动画用 CSS 过渡（淡入/打字机） |
| 后端栈 | Fastify + @fastify/websocket + @fastify/multipart + zod + pino | schema 校验 + 原生 ws 性能；单进程守护 |

## 6. 接口契约

### HTTP

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/send` | 入参 `{ sessionId?, text, images: string[]（imageId 或 dataURL）, providers: Provider[] }` → `{ messageId, replies: [{id, provider}] }` |
| POST | `/api/replies/:id/retry` | 单窗重试（同 provider 单条回复） |
| POST | `/api/replies/:id/stop` | 单窗停止生成 |
| POST | `/api/providers/:id/new-session` | 该站开新会话 |
| GET | `/api/providers/status` | 三家 `{login, ready, generating, adapter}` |
| POST | `/api/providers/:id/recall` | 把离屏窗口拉回屏幕（人工处理验证码） |
| POST | `/api/providers/:id/logout` | 清该站登录态 |
| GET | `/api/diag/selectors?provider=` | 选择器命中报告（站点改版排查） |
| GET/POST/PATCH/DELETE | `/api/sessions[/:id]` | 列表/新建/重命名/删除（含 `?q=` 搜索） |
| GET | `/api/sessions/:id/messages` | 会话全量（含 replies 与 votes） |
| POST | `/api/replies/:id/vote` | `{ kind: 'like' \| 'best' }`，可取消 |
| GET | `/api/export/:sessionId?format=md\|json` | 全量导出下载 |
| GET | `/api/health` | 存活 + 各适配器状态 |

### WS `/ws`

客户端 → 服务端：`{type:'subscribe', sessionId}` · `{type:'ping'}`
服务端 → 客户端：

```ts
type ServerEvent =
  | { type: 'hello'; seq: number }
  | { type: 'reply.started';   reply: Reply }                        // 已投递，等首字
  | { type: 'reply.delta';     replyId: string; text: string; seq: number } // text=累计全文
  | { type: 'reply.done';      replyId: string; content: string; latencyMs: number; firstTokenMs: number; tokenEst: number }
  | { type: 'reply.error';     replyId: string; error: string; code?: 'needLogin'|'risk'|'selector'|'timeout'|'network' }
  | { type: 'provider.status'; provider: Provider; login: LoginState; generating: boolean }
  | { type: 'view.frame';      provider: Provider; jpeg: string; ts: number; fps: number } // 观测窗，按需
  | { type: 'session.created'; session: Session };
```

**`reply.delta` 传累计全文而非增量片段**：前端直接覆盖渲染，天然避免丢帧/乱序导致的文本错乱。

### 数据模型（与你给的保持一致，仅追加可选字段）

```ts
export type Provider = 'deepseek' | 'doubao' | 'kimi';
export type ReplyStatus = 'pending' | 'streaming' | 'done' | 'error';

export interface Message {
  id: string; sessionId: string; role: 'user' | 'assistant';
  content: string; images?: string[]; createdAt: number;
}
export interface Reply {
  id: string; userMessageId: string; provider: Provider;
  content: string; status: ReplyStatus;
  latencyMs?: number; firstTokenMs?: number; tokenEst?: number; error?: string;
  errorCode?: 'needLogin'|'risk'|'selector'|'timeout'|'network';
  adapter?: 'web' | 'api' | 'mock';   // 该条回复实际走哪条通道
}
export interface Session { id: string; title: string; createdAt: number; updatedAt: number; }
export interface Vote { replyId: string; kind: 'like' | 'best'; createdAt: number; }
export type LoginState = 'unknown' | 'loggedIn' | 'needLogin' | 'needManual' | 'error';
```

### 数据库表

## 7. 分步交付计划（每步可独立运行验证）

| 阶段 | 内容 | 验收方式（不依赖登录） |
| --- | --- | --- |
| **P0 骨架** | workspaces + Fastify + Vite + TS + Tailwind + `/api/health`；**先验证 Chromium 能否从当前中文项目路径启动** | `npm run dev` → 打开页面看到健康状态；跑一次 Edge 起 `about:blank` 截图成功 |
| **P1 前端全流程（Mock）** | MockAdapter（可配速度/失败率/思考过程污染）；三窗并发、流式打字机、停止、重试、清空、新会话、顶部开关、耗时/首字/token；聚合页切换控件+状态圆点+淡入、并排模式、投票、导出、会话侧栏、响应式、快捷键 | **纯离线**：不装浏览器、不登录、不联网，两个页面全部交互可点可验 |
| **P2 持久化** | node:sqlite 建表 + 上传落盘 + 会话 CRUD + 导出 + WS 断线重放 | 重启服务后会话与消息仍在；导出文件内容正确 |
| **P3 Playwright 适配层** | 移植 page-utils/site-config；上下文生命周期（离屏/召回/登录探测）；文本三级注入；图片三级注入；发送复核；快照差分抓流；停止/新会话；`/api/diag/selectors`；`scripts/login.mjs`、`scripts/selftest.mjs` | **逐站验收**：豆包 → Kimi → DeepSeek。每站能真实发出并抓到完整回答（含排除思考过程）；`selftest` 打印三站命中报告 |
| **P4 路线 B** | 三家 API 适配器（SSE）+ `ADAPTER_MODE=hybrid` 自动降级 | 配好 Key 后回答与网页版同 UI 呈现；拔掉 Key 自动落到网页通道 |

## 8. 平台限制与降级方案（显式说明）

| 限制 | 现实 | 我们的处理 |
| --- | --- | --- |
| 滑块 / 短信 / 扫码人机验证 | **无法自动绕过，也不打算绕** | `riskWords`/`riskSelector` 命中 → `needManual` → 前端提示 + 一键把窗口召回到屏幕，人工完成后继续 |
| 登录态会过期 | 站点主动踢下线 | `loginState()` 每轮发送前轻量探测；失效 → 前端红点 + "重新登录"按钮（跑 `scripts/login.mjs`） |
| 选择器随改版失效 | 必然发生 | 全字段多候选数组 + `/api/diag/selectors` 诊断 + `selftest` 报告；只改 `site-config.ts` 一个文件 |
| 编辑器内部模型不同步 | Lexical/ProseMirror 会"有字实无字" | 三级注入降级 + 每次注入后**读回校验**，校验不过就换下一级 |
| 长文本被内核截断 | 豆包实测 | 分块 20 字插入 |
| 反自动化检测 | 部分站点识别 headless/Electron | 用**真实 Edge/Chromium + headful + 离屏**；UA 去标记；不用 `--headless` 跑日常 |
| 自动化频率限制 | 高频发送可能被限流 | 同站串行 + 发送间隔下限 + 指数退避重试（最多 2 次） |
| **账号风险** | 违反站点 ToS 可能导致封号/限流 | README 显著提示：建议**专用小号**、仅本机个人对比、禁止批量刷量；默认间隔可调 |
| 网页版拿不到 usage | 无真实 token 数 | 只给"估算值"并标注；耗时/首字延迟是实测真值 |
| 3 个 Chromium 内存 | 约 1.5–3GB | 单机可接受；Docker 里需 `shm_size: 2gb` |
| 微信小程序 | 生产环境无法直连 `ws://localhost`，需**备案域名 + wss + 服务器域名白名单**（开发期可勾"不校验合法域名"） | 列为 P6 之后的可选薄壳：小程序端只做"输入 + 聚合查看"，复用同一套 HTTP/WS 契约（换成 wss） |

## 9. 本机环境障碍与绕行（已实测）

| 问题 | 实测结果 | 绕行 |
| --- | --- | --- |
| `HTTP_PROXY` 指向 `127.0.0.1:10808` 但代理**没在运行** | 所有 npm 请求 `ECONNREFUSED 127.0.0.1:10808` | 命令级清空 `$env:HTTP_PROXY`/`HTTPS_PROXY`（该变量由父进程注入，不是用户级配置） |
| 沙箱禁止写工作区外路径 | npm 默认 cache（`%LOCALAPPDATA%\npm-cache`）报 `EPERM` | 固定用 `npm --cache "D:\MUMUcode\MUMU harness code\.npm-cache"`，并加入 `.gitignore` |
| 无 `ms-playwright` 浏览器缓存 | 需下载约 170MB | 优先 `channel:'msedge'`（已装 Edge 155）；需要 Chromium 时用 `PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright` |
| 项目路径含中文（旧项目实测 Chromium/Electron 起不来） | `AI大乱斗1010` 就是从中文路径启动失败才搬到 `D:\MUMUcode\AI-Arena` | 浏览器 profile/临时文件**外置到纯英文短路径**；P0 第一步就验证本项目路径能否起 Chromium，若不行在 P1 前调整（成本最低） |
| GitHub 推送需代理 | 10808 未监听，`git push` 会失败 | 打 tag 前请启动 v2rayN；否则先本地 commit + tag，网络恢复后补 push |
| `npm`/`pnpm` 的 `.ps1` 被禁止执行 | `npm.ps1 cannot be loaded` | 统一用 `npm.cmd` |
