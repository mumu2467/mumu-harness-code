### 1.4 ★ 引脚分配理由（明确写清"为什么是它、排除了谁"）

1. **为什么 TX/RX 选 17/18**：ESP32-S3 的 **IO_MUX 原生功能里 `GPIO17 = U1TXD`、`GPIO18 = U1RXD`**，正好是 UART1 的硬件默认脚。用它们**不必经 GPIO Matrix 交换**，是延迟最低、最不易出怪问题的一组（随便挑 GPIO4/5 做 UART1 也能用，但要过矩阵）。同时它们在 J1 上连续相邻，杜邦线不易接错。
   > 依据：ESP32-S3 数据手册 IO_MUX 表 —— **待你复核一次**（`datasheet` 章节 "IO_MUX"）。
2. **为什么 RST/RDY 选 16/15**：紧挨 17/18，四根线在排针上构成一条连续排线（15-16-17-18），**接线错误率最低**；且这两个脚是**可选项**（填 `-1` 也能跑主功能），放在"次要脚"上最合理。
   ⚠️ **注意（据 ESP32-S3 数据手册 IO_MUX，请复核）**：GPIO15/16 兼作 **XTAL_32K_P / XTAL_32K_N**。DevKitC-1 **板载没有 32.768 kHz 晶振**，作普通 GPIO 使用**没有影响**；但若将来要加 RTC 晶振做超低功耗休眠，这俩脚要让出来 → 故给出备选方案 B。
3. **为什么不用 33~37**：本机 N8 确实空闲，但老工程对它们只给 `#warning`，而 `N16R8` 模块会被八线 PSRAM 占死。**为免以后换模块返工，直接不用**。
4. **为什么不用 1/2/4/5/6/7/10/11/12/13/14/38/39**：全部**留给第 7.1-E 节的扩展传感器**（雨量计要外部中断脚、第二路 I2C/RS485、电池 ADC 等）。现在不占，是为了让"加传感器只改 `app_config.h`"这条验收标准将来真的成立。
5. **ADC 备注（写给未来的自己）**：GPIO11~20 属 **ADC2**。15~18 做数字 UART 完全不受影响；但**将来做 `EXT_BATT_ADC_PIN`（电池电压）请优先放 ADC1（GPIO1~10）**，避开 ADC2 与射频/未来 WiFi 的已知冲突。
6. **不接 1PPS 的代价（如实说）**：屏幕状态条里"卫星数 / 定位脉冲"只能靠 `gpsext` 的**定位标记**与**是否 stale** 判断，拿不到 1 Hz 秒脉冲。这是**主动放弃**，换来不加电平转换电路。

### 1.5 备选方案（万一 §1.6 核对不通过，或实测有问题）

| 方案 | TX / RX | RST / RDY | 何时用 |
|---|---|---|---|
| **A（已确认采用）** | 17 / 18 | 16 / 15 | 正常情况 |
| **B** | 17 / 18 | **38 / 39**（J3 排针） | 15/16 没引出，或将来要加 32.768 kHz 晶振 |

## 2. ★ DTU 接线复核表（照抄这一节，接错一晚上都调不出来）

### 2.1 逐脚对应表

| DTU 引脚 | 接到哪里 | 为什么 |
|---|---|---|
| `VIN` | **独立 3.8V / 2A DCDC**（★ **绝不接开发板 3V3**） | 开发板 LDO 带不动 10W 发射峰值 |
| `GND` | **ESP32-S3 GND（必须共地）** | 不共地 → "能收到乱码但解析不了" |
| `RXD` | **ESP32-S3 GPIO17（我们的 TX）** | ★★ **交叉接** |
| `TXD` | **ESP32-S3 GPIO18（我们的 RX）** | ★★ **交叉接** |
| `RST` | ESP32 GPIO16（+ 10 kΩ 上拉到 3.3V） | 官方建议"方便异常恢复"；上拉避免 S3 启动瞬间浮空误复位（**RST 低有效为推测，待实测**） |
| `RDY` | ESP32 GPIO15 | 3.3V 输出，联网成功给高电平，可做快速在线判断（内部推挽，**无需上拉**） |
| `1PPS` | **不接** | 1.8V 电平（据 PROMPT），低于 S3 VIH |
| `DTR` / `BOOT` / `Relaod` | **不接** | 本方案不使用 |
| `4G 天线`（IPEX 1 代） | **必须接** | 不接 = 永远注册不上网 |
| `GPS 天线`（IPEX） | **必须接，且必须放室外/窗边** | 官方原文："GPS需要在室外，空旷的地方定位，**室内无法定位**" |

### 2.3 接线三重检查（会写进 README 的 FAQ）

1. `RXD`/`TXD` 是**交叉接**（DTU 的 `RXD` 接 MCU 的 **TX**）。文档里引脚名是**模块侧**视角，这是最容易错的一处。
2. **必须共地**（DTU 与 ESP32 的 GND 直接连）。
3. DTU 的 `VIN` **绝不能**接开发板 3V3。

> **可选增强（推荐，成本一个 P-MOS + 2 个电阻）**：用 GPIO 控制 DTU 的 `VIN` 高边开关。官方明确建议"硬件设计能控制模组的复位脚**或者电源脚**"，这样即使不接 `RST` 也能自动断电重启。

## 3. ★ 供电方案（为什么不能用 3.3V）

### 3.1 为什么绝对不能用开发板的 3.3V

- 开发板 `3V3` 来自板上 LDO，电流能力有限，**完全带不动 10W 的 4G 发射峰值**（3.8V 下 2 A 级）。
- 官方两条（据 PROMPT 引用官方文档）：
  「推荐 3.8V 2A 的 DCDC 芯片供电。**不要用 3.3V** 防止纹波导致电源跌了」；
  「特别是用 3.3V 串口工具的电源功率不足，**设备会异常**」。
- 典型故障表现：DTU 反复重启、注册不上网、发到一半掉线，而 ESP32 侧日志看着一切正常 —— 极难排查。

### 3.2 推荐供电方案

| 场景 | 方案 |
|---|---|
| **桌面调试** | **独立 3.8V/2A DCDC 电源**（或 3.7V 锂电直供，DTU 支持 3.3~4.2V），与 ESP32 的 USB 5V **分开供电、只共地** |
| **野外长期部署** | 太阳能板 → MPPT/充电管理 → 3.7V 锂电组 → **3.8V DCDC → DTU**；ESP32 + 传感器 + 屏由 3.3V LDO 从同一电池取电 |
| **DCDC 选型要求** | 输入 5V（桌面）或电池电压（野外）；输出 **3.8V，连续 ≥2 A、瞬态 ≥3 A**；开关频率高、低纹波；带软启动（抑制上电冲击） |
| **锂亚电池** | 官方明确"3.6V 锂亚电池供电**要加电容**"（锂亚内阻大，扛不住发射脉冲） |

### 3.3 去耦电容（放在 DTU `VIN`/`GND` **10 mm 以内**）

| 位号 | 取值 | 作用 |
|---|---|---|
| C1 | **1000 µF / 10 V 低 ESR 电解** | 吸收 4G 发射脉冲（主储能） |
| C2 | **100 µF / 10 V 陶瓷或钽** | 中频去耦 |
| C3 | **100 nF 陶瓷** | 高频去耦，最贴近引脚 |
| 若用锂亚电池 | 再并联 **≥2200 µF** | 补偿电池内阻 |

- 起步按上表做，**实测掉电/重启就继续加大 C1**（并 2×470 µF 比一颗 1000 µF 的 ESR 更低）。
- 可选：`VIN` 串一颗磁珠或 **0.5~1 A PPTC**，抑制上电冲击与相互干扰。

### 4.2 野外估算（工作例：60 s 上报、常驻不休眠）

- 日均耗电：`0.2 A × 24 h = 4.8 Ah/天`（@3.7 V ≈ 17.8 Wh/天）
- 太阳能板：按等效峰值日照 3.5 h/天、系统效率 0.75 → `17.8 ÷ (3.5 × 0.75) ≈ 6.8 W` → **留 2 倍余量取 15 W 板**
- 电池：按 **3~5 天连续阴雨** → `4.8 Ah × 4 天 ≈ 19.2 Ah@3.7V` → 12 V 系统约 6 Ah，选 **12 V 7 Ah** 或 **3.7 V 20 Ah 锂电组**
- **SIM 流量**：单条 JSON 约 400 B；`400 B × 1440 条/天 = 576 KB/天`；加 HTTP 头/请求行（约 250 B/条）→ `+360 KB/天` ≈ **0.94 MB/天 ≈ 28 MB/月** → **按 50 MB/月 申请余量**
- ★ **省流量要点**：`config,get,gpsext` 是**本地串口命令**（DTU 固件直接问内部 GNSS），**不产生流量**；只有 HTTP 上报和 `lbsloc`（基站定位）才走 4G。
- 若做超低功耗：改用 DTU 周期唤醒（10 min 周期约 2.4 mA / 60 min 周期约 520 µA，3.7 V/500 mAh 可用约 40 天），此时应把数据流切成**方案 (a)**，让 DTU 自己上报。

### 5.3 阶段 1 结论

> 方案 A（`TX=17 / RX=18 / RST=16 / RDY=15`）**成立**：4 个脚全部空闲、非 strapping、不在 26~32、不撞现有 I2C/SPI/UART0/USB，且 17/18 正好是 ESP32-S3 **UART1 的 IO_MUX 原生脚**。
> DTU 供电**必须独立 3.8 V/2 A + 1000 µF/100 µF/100 nF 去耦**，**禁止**用开发板 3V3。
> **唯一阻塞项**是 §5.1 的"HTTP 通道参数配置方式"，需确认后阶段 4 才能定形。
