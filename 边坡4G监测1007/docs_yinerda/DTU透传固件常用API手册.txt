十四、时间类API
关于时间，调用config,get,nettime命令获取的时间并不一定可靠。这个时间来源于基站时间或者网络时间。
网络时间基于网络，如果没网络时间肯定不对，有的基站本身时间就是错误的；NTP也可能刚开始同步失败，导致模块时间错误。如果您的设备要时间很严格；可以做业务逻辑实现，让自己的服务器与设备之间同步时间。
如果需要离线的时候和网络异常的时候时间也正确，需要使用本地RTC时钟芯片方案。
编号
 | 项目
 | 描述

1
 | API
 | ProSetNeedNtp(）

功能
 | 主动同步一次NTP时间

参数
 | 无

返回值
 | 无

说明
 | 1、V1.1.10及其以后的支持
2、使用的时候，内部会自动调用NTP同步功能。通过ProGetNtpSta() 返回值判断是否同步成功。返回1表示同步成功。

编号
 | 项目
 | 描述

2
 | API
 | ProGetNtpSta()

功能
 | 判断NTP时间同步是否成功

参数
 | 无

返回值
 | 0:没有同步时钟或者同步失败
1:同步成功

说明
 | 1、V1.1.10及其以后的支持
2、如果开启了NTP功能，固件会自动同步一次，通过ProGetNtpSta() 返回值判断是否同步成功。返回1表示同步成功。一般同步后时间可以认为是可信的。
3、返回为1只表示上一次同步成功，如果设备运行了很久不表示时间是准确的，模组内部RTC也会有误差，建议30分钟或者1小时调用ProSetNeedNtp(）同步一次

2
 | API
 | SmsGetCh()

功能
 | 读取收到的短信，读取后会自动删除收到的短信

参数
 | 无

返回值
 | nil表示无数据
table类型 表示有数据table的元素如下:
t[1]:发短信的号码 string
t[2]:收到短信的内容 string
t[3]:短信的附加信息(table格式，可以转换成json看结构，可以不需要)

说明
 | 使用方法，DTU WEB平台，先配置短信为保存模式，然后才能使用API读取
local t = SmsGetCh()
if t then 
log.info("SmsGetCh.test",t[1],t.[2],json.encode(t[3]))
end
